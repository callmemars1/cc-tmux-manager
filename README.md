# cc — менеджер tmux-сессий с Claude Code

Единица работы — **задача**, а не директория. Одна задача = одна tmux-сессия с
запущенным в ней Claude Code. Сессия называется по смыслу задачи, поэтому
`cc ls` читается как список того, чем сейчас занят каждый агент.

## Требования

- `bash`
- `tmux`
- `claude` в `PATH` (или путь в `CLAUDE_BIN`)

## Установка и обновление

```bash
curl -fsSL https://raw.githubusercontent.com/callmemars1/cc-tmux-manager/main/install.sh | bash
```

Ставит последний релиз в `~/.local/bin/cc`. Тот же скрипт обновляет — повторный
запуск просто подменяет файл на новую версию. Из клона: `./install.sh` поставит
лежащий рядом `cc`.

Обновиться можно и самим `cc` — он скачивает и запускает `install.sh` для того
пути, откуда запущен:

```bash
cc update
cc version
```

Либо симлинком, чтобы обновляться через `git pull` (`install.sh` в этом случае
откажется перезаписывать симлинк, пока не передать `CC_FORCE=1`):

```bash
ln -s "$PWD/cc-tmux-manager/cc" ~/.local/bin/cc
```

Переменные `install.sh`:

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `CC_INSTALL_DIR` | `~/.local/bin` | куда ставить |
| `PREFIX` | — | альтернатива: ставит в `$PREFIX/bin` |
| `CC_REF` | — | взять `cc` из ветки/тега вместо последнего релиза |
| `CC_REPO` | `callmemars1/cc-tmux-manager` | откуда брать |
| `CC_FORCE` | — | `1` — перезаписать `cc`, установленный симлинком |

## Команды

| Команда | Что делает |
| --- | --- |
| `cc "задача словами"` | новая сессия с временным именем `t-HHMMSS`; Claude сам переименует её по смыслу задачи |
| `cc <slug> [задача...]` | явное имя сессии (аргумент без пробелов — это слаг, а не задача) |
| `cc -C <dir> <slug> [...]` | то же, но в другой рабочей директории |
| `cc s` (или без аргументов) | выбрать сессию стрелками и подключиться |
| `cc n [slug]` | написать задачу в `$EDITOR`; сессия стартует после сохранения |
| `cc ls` | плоский список: подключена ли, чем занята, последняя строка вывода |
| `cc a <slug>` | подключиться, отобрав сессию у зависшего клиента |
| `cc peek <slug>` | хвост сессии, не подключаясь |
| `cc mv <old> <new>` | переименовать сессию (лог переезжает вместе с ней) |
| `cc log <slug>` | писать вывод сессии в `~/.cc-logs/<slug>.log` |
| `cc kill <slug>` / `cc killall` | убить сессию / весь tmux-сервер |
| `cc update` | обновить сам `cc` до последнего релиза |
| `cc version` (или `--version`) | версия установленного `cc` |
| `cc help` (или `-h` / `--help`) | список команд и переменных окружения |

Если сессия с таким именем уже есть, `cc <slug> задача` не создаёт новую, а
досылает текст в существующую.

### `cc s` — выбор сессии стрелками

`↑`/`↓` (или `k`/`j`) — двигаться по списку, `Enter` — подключиться, `q` или
`Esc` — выйти. Строки те же, что у `cc ls`. Список длиннее экрана прокручивается
окном, узкий терминал обрезает строки по ширине.

Пикер требует терминал: если вывод уходит в пайп или в CI, `cc s` (и `cc` без
аргументов) печатает тот же плоский список, что `cc ls`, и выходит — так
`cc | grep` продолжает работать.

### `cc n` — задача из редактора

Открывает `$VISUAL`/`$EDITOR` (по умолчанию `vim`) на временном файле. Сессия
создаётся только после сохранения и выхода: пустой файл или ненулевой код
выхода редактора — ничего не происходит. Удобно для длинных многострочных
задач, которые неудобно передавать одним аргументом.

Многострочный текст доезжает целиком: в новую сессию — одним аргументом
`claude`, в уже существующую — через bracketed paste, поэтому Claude не
отправляет первую строку как отдельный запрос.

`cc n <slug>` задаёт имя сессии явно (иначе — временное `t-HHMMSS` с
автопереименованием), `cc -C <dir> n` — рабочую директорию.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `CC_DIR` | текущая директория | рабочая директория новых сессий |
| `CC_AUTOLOG` | выключено | `1` — включать `pipe-pane` сразу при создании сессии |
| `CC_AUTONAME` | `1` | `0` — не просить Claude переименовывать временную сессию |
| `CLAUDE_BIN` | `claude` | чем запускать Claude Code |
| `CLAUDE_FLAGS` | пусто | доп. флаги к запуску |
| `VISUAL` / `EDITOR` | `vim` | чем открывать задачу в `cc n` (`VISUAL` приоритетнее) |
| `CC_REPO` | `callmemars1/cc-tmux-manager` | откуда обновляется `cc update` |

## Как работает автопереименование

Сессия из `cc "задача словами"` стартует под именем `t-HHMMSS`. Claude получает
через `--append-system-prompt` инструкцию вывести из первого запроса короткий
kebab-case слаг и вызвать `cc mv t-HHMMSS <slug>`. Отключается через
`CC_AUTONAME=0`.

`cc ls` и `cc s` показывают задачу из `pane_title`: Claude Code кладёт туда
текущее занятие, обычный шелл — `user@host:cwd` (в этом случае выводится только
`cwd`).

## Версионирование и релизы

Версия живёт в одной строке `CC_VERSION="X.Y.Z"` в начале `cc`. Релиз делается
бампом этой строки: как только новое значение приезжает в `main`, workflow
`release` создаёт тег `vX.Y.Z` и релиз с файлами `cc` и `install.sh`. Пуш без
бампа не делает ничего, повторный запуск на том же значении — тоже.

`install.sh` без `CC_REF` качает `cc` из
`releases/latest/download/cc`, поэтому `cc update` всегда приносит последний
релиз, а не состояние `main`.

Workflow `ci` на каждый PR и пуш в `main` проверяет `bash -n`, `shellcheck`,
что `CC_VERSION` — валидный semver, и что установка/переустановка работает.
